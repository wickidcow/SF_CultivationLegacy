# Cultivation 1.1.24 — Adventure colors and compatibility preservation

Cultivation's remaining SefiLib Theme color migration is now implemented with Adventure TextColor. This update keeps existing crop/item IDs, recipes, stored experience, discoveries, Seed Pack contents and gameplay rates intact.

## Improvements

- Replaced the 19 Bungee ChatColor-based palette declarations with Adventure colors, while retaining all original palette values and labels.
- Added a binary-compatible modern Theme implementation. Old ChatColor constructors/getColor remain as explicitly deprecated compatibility bridges for existing compiled consumers; ordinary Cultivation code no longer calls them.
- Fixed RGB color downsampling when constructing plant display lore, prefixing Seed Pack item names and substituting recipe-scroll text.
- Preserved exact historical lowercase hex encoding, legacy formatting tokens and SefiLib item-lore layout.
- Removed an obsolete 1.x version-number check from the item-display rotation correction. All supported versions retain the intended orientation without parsing the newer 26.x numbering as an old minor version.
- Completed the earlier ItemMeta lore/name migration and aligned the provided build API with Slimefun Legacy 4.1.78.
- Enforced zero deprecated/removal source diagnostics across Paper 1.21.11, 26.1, 26.2 and 26.3 compilation.
- Added original-library ABI/color parity tests and packaged-addon runtime integration checks. Test code and test-only dependencies are excluded from the released plugin.
- Added runtime recovery checks: malformed saved codex data must not be replaced with an empty file, and unrelated experience data must remain unchanged.

## Compatibility and installation

The distribution remains Java 21 bytecode with a Minecraft/Paper 1.21.11 minimum. CI tests actual Paper 1.21.11 with Java 21 and Paper 26.3 with Java 25, using Slimefun Legacy 4.1.78. Use the Java runtime required by your server version.

This release does not newly enable or certify Folia support. Its tests do not replace real-player validation of every inventory interaction or third-party server integration.

Back up the Cultivation folder and your normal server/world data. Stop the server, replace the old Cultivation JAR with SF_Cultivation1.1.24.jar, and start normally. Keep the existing configuration, exp.yml and codex.yml; no data reset is required. Do not use a plugin hot-reload for this update.
